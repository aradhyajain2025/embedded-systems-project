# Teammate guide: running the full demo

Follow it top to bottom. Everything runs in simulation, no hardware.

The demo has two halves that meet at one text line, the UART frame, for example `P:1,D:15,S:1*79`.
- **Firmware half (MPLAB X + XC8):** the PIC16F877A code produces frames in the simulator's UART window.
- **PC half (Python):** reads those frames, checks the checksum, groups 20 frames into a window, scores it with an Isolation Forest and prints `ok` or `ALERT`.

---

## 1. What is in the folder

### Firmware files (go into MPLAB X, never run in Python)
| File | What it is |
|---|---|
| `main.c` | Timer2 interrupt (200 ms tick), hardware USART at 9600 baud, main loop that builds and sends a frame. `USE_FAKE_SENSORS` is 1. |
| `frame.c`, `frame.h` | `frame_build()` writes `P:x,D:y,S:z*CS` and a newline. CS is the XOR of the payload, two uppercase hex digits. |
| `sensors.c`, `sensors.h` | Real sensor read functions (PIR, sound, ultrasonic with Timer1). Compiled but not called while `USE_FAKE_SENSORS` is 1. |
| `fake_sensors.c`, `fake_sensors.h` | The 400 frame scripted table: 200 normal, 100 intruder, 100 normal. It repeats after 400 frames. |

**Add only one table file to MPLAB.** `fake_sensors_generated.c` has the same content as `fake_sensors.c` (only a trailing newline differs). If you add both, the linker reports duplicate symbols. Use `fake_sensors.c` and leave the other one out.

### Python files (run from PowerShell, never added to MPLAB)
| File | What it is | Needed? |
|---|---|---|
| `live_serial.py` | The one you run in the demo. Reads frames, scores windows. | Yes |
| `ids_pipeline.py` | Windows, features, Isolation Forest. | Yes |
| `frames.py` | `parse_frame()` and `checksum()`. | Yes |
| `generator.py`, `maker.py` | Make the normal training data. `generator.py` imports `maker.py`. | Yes |
| `run_demo.py` | The detection results run (about 9 s). Writes `anomaly_scores.png`. | Yes |
| `frames_log.txt` | Saved firmware output (516 frames). The fallback. | Yes |
| `anomaly_scores.png` | The plot, regenerated by `run_demo.py`. | Nice to have |
| `export_c_array.py` | Made the table. **Do not run it.** See section 7. | No |
| `simulator.py`, `roundtrip.py`, `testparser.py` | Old or test files. | No |

Docs: `RUNBOOK.md` (the script for the demo), `PRESENTATION_PLAN.md` (who says what), `TODO.md`.

## 2. One time setup (do this tonight)

### 2a. Python
1. Install Python 3.10 or newer from python.org. Tick **Add python.exe to PATH** in the installer.
2. Open PowerShell and check: `python --version` (if it says not found, try `py --version` and use `py` instead of `python` everywhere below).
3. Install the packages. First try the versions Aradhya tested, so the scores match:
```
python -m pip install scikit-learn==1.9.1 numpy==2.3.4 matplotlib==3.10.9 pyserial==3.5
```
If that fails (for example an older Python), install without versions: `python -m pip install scikit-learn numpy matplotlib pyserial`. Scores may then differ slightly from the RUNBOOK. That is fine, just do not read exact numbers off the RUNBOOK.

### 2b. Copy the files
1. Make a folder, for example `D:\embedded_project`.
2. Copy **all** the files from Aradhya into it, flat, no sub folders.
3. In PowerShell: `cd D:\embedded_project`. Every command below runs from this folder.

### 2c. Smoke test the Python side (no MPLAB needed)
```
python live_serial.py frames_log.txt
```
Expected output:
- first line `Trained on 3000 normal frames -> 150 windows`
- then 25 lines starting `window   1` to `window  25`
- `ALERT` on windows 3, 11, 12, 13, 14 and 23, `ok` on all others (window 15 is `ok`, a miss)
- last line `Done: 25 windows scored, 0 frames rejected, 16 frames left over (less than one window)`

If you see that, the PC side works. If a few windows differ, the package versions differ, so go back to the pinned install.

## 3. Firmware in MPLAB X

You already have a project that works. Check it against this list. If you start a new one, follow the whole list.

1. **Device:** PIC16F877A. **Compiler:** XC8 (v2.x, the code uses `__interrupt()` syntax). **Tool:** Simulator.
2. **Source files in the project:** `main.c`, `frame.c`, `sensors.c`, `fake_sensors.c`. Headers `frame.h`, `sensors.h`, `fake_sensors.h` sit next to them. Do **not** add `fake_sensors_generated.c`.
3. **Check these two lines in `main.c`:** `#define _XTAL_FREQ 4000000` and `#define USE_FAKE_SENSORS 1`.
4. **Simulator clock:** the code assumes a 4 MHz crystal. Set the simulator's frequency to 4 MHz so the 200 ms tick and 9600 baud are correct (Project Properties, Simulator category, oscillator or frequency option; menu names vary by version).
5. **UART output window:** in Project Properties, Simulator category, enable **UART1 IO** and send the output to a **Window**, baud 9600. Output then appears in the **UART 1 Output** tab of the Output pane.
6. **Build:** Production > Clean and Build Main Project. It must finish with `BUILD SUCCESSFUL`.
7. **Run:** Debug > Debug Main Project, then press Continue (run). Frames like `P:0,D:253,S:0*49` should start scrolling in UART 1 Output.

Nothing in the firmware needs editing for the demo. Do not change `main.c`, because the saved log and the table pattern depend on it.

## 4. Demo flow (matches PRESENTATION_PLAN.md)

### Before you start talking (step 1 of the plan)
1. PowerShell open in the project folder, font enlarged (Ctrl + scroll).
2. Run `python run_demo.py` once so packages are warm and `anomaly_scores.png` is fresh.
3. MPLAB X open with the project built. **Start the firmware as Aradhya begins step 1**, so frames are already in the window by step 4.

### Step 2 and 3: your part (about 1.5 minutes)
- Show the UART 1 Output window. Point at one frame, for example `P:1,D:15,S:1*79`: payload, then `*`, then two hex digits of checksum.
- Say what the firmware does: Timer2 interrupt gives a frame every 200 ms (5 per second), hardware USART at 9600 baud, Timer1 is the microsecond counter for echo timing.
- Say: sensor values come from a table in the firmware because there is no hardware. The `USE_FAKE_SENSORS` switch selects the real read functions, which we did not run in simulation.
- Say: the table is scripted, but every frame goes through the real framing, checksum and UART code.

### Step 4: the live copy (about 1 minute)
You need **about 300 frames** in the window (60 s at 5 per second). The intruder part of the table is frames 200 to 300. In the dry run, time how long the simulator takes to reach 300 frames, because the simulator may run slower than real time.

1. Pause the simulation (Pause button) so the window stops moving.
2. Click inside the **UART 1 Output** window, press **Ctrl+A**, then **Ctrl+C**.
3. In PowerShell, run:
```
Get-Clipboard | python live_serial.py -
```
(the `-` at the end is required, it means "read from the clipboard text".)

What you should see: `Trained on 3000 normal frames -> 150 windows`, then one `window N` line per 20 frames, then `Done:`.
- `rejected so far: 0` is ideal. A rejected count of 1 or 2 is fine: it is usually a half frame at the end of the copy or a header line. Say so if asked.
- If you copied from firmware reset, the alert pattern should be like the saved log: alerts around windows 11 to 14 (the intruder part), with 15 sometimes missed, and a false alarm around window 3. [Likely, not guaranteed]
- Say it honestly: this is copy then score, **not live streaming**.

### Step 5 onward: Aradhya's part
Aradhya runs `python run_demo.py` and shows `anomaly_scores.png`, then talks about limits. Stay ready for embedded questions (section 6).

## 5. If something goes wrong

| Problem | Do this |
|---|---|
| MPLAB X crashes or will not build | Show your UART screenshot, then run `python live_serial.py frames_log.txt` (same 516 frames from an earlier firmware run). Say the log is from an earlier run. |
| Pasted clipboard gives 0 or very few windows | You copied too early or from the wrong tab. Run the firmware longer and copy from **UART 1 Output**, or use `frames_log.txt`. |
| `python` not found | Use `py` instead of `python`, or reinstall Python with Add to PATH ticked. |
| `ModuleNotFoundError: sklearn` (or numpy, serial, matplotlib) | `python -m pip install scikit-learn numpy matplotlib pyserial` |
| `frames_log.txt` missing | Make a new one from MPLAB: copy the UART window, then run `Get-Clipboard \| Set-Content -Encoding utf8 frames_log.txt`. (Do not use plain `>`, it writes UTF-16 and the script cannot read it.) |
| Window pattern differs from the saved log | Fine for a live copy. Do not hide a miss or a false alarm, say what it is. |
| Linker error `multiple definition of fake_sensors_next` | Both `fake_sensors.c` and `fake_sensors_generated.c` are in the project. Remove one. |
| Plot did not open | `run_demo.py` only saves it. Run `start anomaly_scores.png`. |

## 6. Embedded questions you will probably get

Write your own answers, these are only prompts.
- Where is the embedded part? (Timer2 ISR, USART, framing and checksum, Timer1 echo timing, all on the PIC.)
- Why those peripherals? Why 9600 baud, 4 MHz, SPBRG = 25? (Check: 9600 baud with BRGH = 1 at 4 MHz gives SPBRG = 25, about 0.16% error.)
- How is the checksum built? (XOR of every payload character before the `*`, two uppercase hex digits.)
- What is the fake table and why? (Scripted 400 frame table, no hardware available.)
- What does `USE_FAKE_SENSORS` do? (Switches `main.c` to the real `sensor_read_*` functions, never run in simulation.)
- Why does the ML run on the PC? (The PIC16F877A cannot hold the model.)

**Do not claim:** CCP capture or interrupt on change. The firmware does not use them. It uses Timer2 interrupt for sampling, the hardware USART, Timer1 as a microsecond counter, and polled digital sensors. You may say CCP and interrupt on change would suit real hardware, but they are not implemented.

**Do not claim:** live serial streaming, real sensor results, or real world accuracy. All data is simulated and scripted.

---

## 7. Do not change these

- Do not run `export_c_array.py`. It rewrites the table, and then the saved `frames_log.txt` no longer matches the firmware.
- Do not edit `main.c`, `frame.c` or the table. The frame format (`P:x,D:y,S:z*CS`) is what the Python parser expects. Changing it makes every frame get rejected.
- Do not rename Python files. They import each other by name.
